English abstract

dsh-effort-router helps users balance answer quality and reasoning cost for each step of an agent task. A user may either pin a specific reasoning level or choose Auto. In Auto mode, the product considers the original task, recent failures, repeated tool activity, information volume, and budget pressure before selecting the actual level for each step. A concrete user choice always takes priority. The product uses the host application's native model selector and read-only displays rather than adding a separate settings interface.

Delivered direction (0.2.18-agent.2): DSH 0.2.2 support preserves both the existing DSH 0.2.1 path and continuous Auto scheduling throughout a turn. The logical Auto selection is resolved synchronously at the host's per-step selection capture; re-planning happens when the native raw selection changes within a step. Scheduled modern Auto performs no model.select() write and appends no Auto selection event; a manual pick stays manual on later turns until the user explicitly returns to Auto. The only selection write left restores an unsupported manual effort after it had to be omitted. Official Auto means omitted effort with adapter defaults; it does not replace this evidence-driven scheduler.

Native global memory; F-06 frozen: DSH already remembers the latest explicit provider, model, and Auto/concrete-level choice across new sessions and restarts. The plugin will not build a second preference store or per-model memory. It only needs to preserve the native logical choice, schedule Auto after restoration, and avoid recording Auto's temporary outputs as new user intent.

1. 文档目的与产品目标

本文记录当前版本已经提供的能力（含 0.2.18-agent.1 的 T-01～T-09 与 0.2.18-agent.2 的 T01～T07 交付；T08 的 Web 冒烟已验、Desktop 待验收）、仍存在的边界与已接受残留，以及 DSH 原生全局选择记忆；随后用独立登记册保留全部已批准、已否决、冻结与延期选项。不同状态会明确区分，避免把计划能力或讨论项误读为当前能力。技术任务和版本安排见 开发计划。

1.1 目标用户与场景

  • 同一任务中既有简单问答，也有编码、检索、排错和多步工具调用，希望按步骤动态调整强度的用户。
  • 使用子代理拆分任务，希望父会话的手动选择或 Auto 意图得到正确继承的用户。
  • 使用手写自定义模型，希望在未自行配置时获得基本推理档位选择的用户。
  • 经常新建会话或重启应用，不希望反复恢复上次档位偏好的用户。

1.2 明确不做的产品方向

  1. 不替用户选择供应商或模型，只调整所选模型的推理强度。
  2. 不提供独立设置页、第二套滑条或另一个档位控制中心。
  3. 不承诺固定的成功率或节省比例；自动调度是辅助策略，不是质量保证。
  4. 不考虑与 think-level 的共存兼容。本项目不为该插件保留协同入口、自动让位或联合控制逻辑。

2. 使用概念与基本约定

概念面向用户的含义
一轮对话从用户提交指令开始，到本轮回答及相关工具活动结束。一轮中可能包含多个模型执行步骤。
具体档用户明确选择的某个推理强度。它代表人工决定，产品应尊重。
Auto一种持续的模式选择，而不是某一个固定强度。只要用户没有改选，本轮每个步骤都交给调度器重新判断。
实际执行档某一步真正使用的强度。Auto 下不同步骤可以不同，但这不会改变用户仍处在 Auto 模式的事实。
任务类型产品对任务始发需求的理解，例如轻量、一般、工程或高复杂任务。它只决定起点，后续仍看实际证据。
逻辑偏好用户明确选择的 Auto 或具体档。跨会话记忆保存的是它，而不是 Auto 某一步产生的实际执行档。
核心约定：用户在一轮开始时选择 Auto，整轮就都保持 Auto 持续调度；只有用户主动改选，才退出 Auto。某一步被换算成具体执行档，不等于用户改成了手动模式。

3.1 Auto 实际发送档如何计算 核心创新

Auto 不是简单地“永远使用最高档”或“记住上次实际档”。它在每个执行步骤重新收集证据：先由任务简报确定起点，再叠加近期困难与有效信息量，扣除节俭信号，最后经过安全约束和模型能力映射，得到当前步骤真正发送的档位。

用户选择 Auto
当前步骤开始；逻辑模式始终保持 Auto
↓
① 任务简报决定起始强度
轻量 / 一般 / 工程 / 高复杂
当前默认起点：较低 / 较低 / 较高 / 最高
↓ 同时读取三类证据

②A 近期困难与事件证据

  • 工具报错，近期证据权重更高
  • 同参数工具调用重复出现
  • 待办刚完成，需要推进下一项
  • 子代理返回，需要整合结果
  • 上下文刚压缩，需要校验信息保真
  • 上一任务有未解决失败
向上调整；合并后默认最多 +2 级

②B 长窗口有效信息量

  • 累计任务简报的有效信息量
  • 累计工具结果的有效信息量
  • 重复文本经过压缩折扣，不当作等量新知识
  • 两类信息量分别越过分级阈值
取两类中较强升档信号：0 / +1 / +2 级

②C 实时节俭信号

  • 当前是子代理执行
  • 上下文占用达到压力阈值
  • 会话总量超过用户启用的预算
任一成立可向下调整 1 级
↓ 三路证据合成
目标强度 = 任务起点 + 困难与事件升档 + 信息量升档 − 节俭降档
↓ 先约束目标，再映射到模型真实能力

③ 目标强度安全约束

  • 任务初期不低于合理的起始强度
  • 轻量任务的总升档幅度有限
  • 不超过高复杂任务所允许的上限
  • 普通 Auto 永不主动关闭思考

④ 模型能力与用户允许范围

  • 只从当前模型真实提供的档位中选择
  • 再按用户设置的允许档位过滤，判断以模型最终档位名为准
  • 目标不存在时按既定方向取可用档
  • 未知档位按模型声明顺序推断强弱；混合已知与未知档位时保证严格先后，不出现并列
↓
⑤ 得到当前步骤实际发送的档位

只读徽标显示该实际档与理由 → 下一步仍保持 Auto，重新读取最新证据并计算

一个简化示例

某普通任务从“较低”开始；近期出现足够的工具错误证据，向上调整 1 级；信息量没有越档，也没有节俭信号，因此目标变为“中等”。如果当前模型只提供“较低”和“较高”，默认的“接近且偏强”规则最终会选择“较高”作为实际发送档。下一步若错误证据衰减，目标可以重新下降，但用户仍然处于 Auto。

手动模式不参与上述计算：用户选择具体档时直接尊重人工选择；只有 Auto 才经过这套证据流程。跨会话记忆恢复的也是 Auto 或具体档这一逻辑选择，而不是流程中某一步的实际发送档。

4. 功能需求

当前能力 本节描述产品应具备并持续保持的行为；本轮已交付的修复见第 9 节 F-01/F-02 与第 11 节状态提示，仍待人工复测的场景见第 10 节末尾。

4.1 模式选择与用户接管

编号需求验收方式
FR-001支持推理强度选择的模型应提供 Auto 入口；不支持推理的模型不得出现虚假的强度选择。分别检查思考模型、仅关闭档模型和不支持推理的模型。
FR-002用户选择具体档后，必须按该档执行，不得被自动调度改写。在连续步骤、工具调用和子代理中检查人工选择是否保持。
FR-003模型不接受某个档位时，不得伪造另一档冒充用户选择，应安全忽略该档位并说明。使用不支持目标档的模型验证请求仍能继续。
FR-004插件被关闭或内部判断失败时，普通请求应继续可用，虚拟 Auto 不得误发给模型。注入异常、关闭功能并检查请求是否能够安全继续。
FR-005插件重载或第三方组件变化后，Auto 入口与请求处理不得互相遗留、重复或失效。重复挂载、重载及与其他显示组件交替变化后检查。

4.2 任务理解与动态调度

编号需求验收方式
FR-010产品应根据用户最初提交的任务判断难度起点，而不是被后续大段工具输出误导。比较多行简报、普通问答、工程需求及只有工具结果的恢复会话。
FR-011系统通知、技能说明、压缩摘要等自动插入内容不得被当作用户的新任务。插入各类通知后，任务起点和预算判断不应被重置。
FR-012Auto 应考虑近期工具失败和同参数重复调用，在需要排错或摆脱循环时提高强度。构造首次失败、连续失败、重复读取与并行工具结果，观察是否按证据调整。
FR-013Auto 应考虑任务简报和工具结果的有效信息量，重复文本不应等同于新知识。比较短任务、长任务、循环日志和多样化内容；多行简报不得被重复计量。
FR-014待办完成、子代理返回和上下文压缩后的整合步骤，可作为提高强度的证据；被关闭的信号不得在重新开启后补放。分别验证信号开启、关闭、重新开启及新事件发生时的行为。
FR-015上下文或预算紧张，以及子代理执行时，可适当降低强度；任务初期仍应保留合理的难度起点。检查预算阈值、子代理和任务初期之间的取舍。
FR-016Auto 不得主动关闭思考；只有明确证据表明历史已不兼容思考模式时，才可进入保护性恢复。普通无推理块消息不得误判；确证的历史问题应可恢复并在解除后释放。
FR-017不同模型的可用档位不一致时，应选择安全、可解释的实际档，不得选择模型未提供的档位。混合已知与未知档位时，强度顺序必须严格递增，不得把两个不同档位算成同一强度。覆盖标准档位、自定义档位、较多未知档位及允许范围为空的情况；每个档位在其自身强度上都必须能被精确选中，三种回退方向都不得越出允许范围。

4.3 整轮 Auto、子代理与分支连续性

编号需求验收方式
FR-040用户在一轮开始时选择 Auto 后，整轮都必须保持 Auto 持续调度。每一步的实际档可以变化，但不得把下一步误认成手动定档。插件只在本步请求 capture 时把逻辑 Auto 解析为实际档，不写入具体档位的持久选择；回合外的原生选择与配置恢复仍保持 Auto。同一轮使用多个步骤和工具调用，确认每步都重新调度，模式始终显示 Auto；回合外恢复配置时不得把实际档固化成人工选择。
FR-041用户在整轮中途改选具体档，应立即退出 Auto；之后不得因旧记忆或上一步结果自动切回。Auto 执行若干步骤后手动改档，检查后续步骤和记忆更新。
FR-042父会话使用具体档时，子代理应继承该档；父会话使用 Auto 时，子代理按自己的任务独立调度。分别验证父手动、父 Auto、父会话继续执行后再返回的子代理。
FR-043无法确认子代理来源时，应采取保守继承，不得把可能的人工选择当成 Auto。子代理创建时冻结父会话当时的调度时代，此后父会话的新决策不影响该子代理的判断。缺少父记录、档位不匹配、显式子代理覆盖及关闭思考的血缘；父会话先手动接管再回到 Auto 时，子代理仍按冻结时代判断而不是被新记录带走。
FR-044会话恢复或分支切换后，不得把旧分支的错误、信息量和任务起点错误带入新分支。投影被整体替换时，证据与简报计量必须原子重建，而不是按增量继续累加。切换到内容不同、长度不同或相同的分支；替换分支后旧错误、旧重复与旧工具体量必须归零，而内容缩短但未被替换时快照保持不变。

4.4 自定义模型的基本档位支持

编号需求验收方式
FR-050对从未配置推理档位的自定义模型，产品可在明确解析出「该模型没有任何可用档位」后补充一套基本选择；缺少模型元数据不算确认。未配置模型获得基本档位；已有配置的模型保持不变；元数据缺失或解析失败时只提示、不写配置。
FR-051用户在模型管理界面明确接管或关闭某个模型后，产品不得在下次启动时擅自补回。关闭、保存、重载和重启后，用户选择仍被尊重。
FR-052自动补充不得增加“关闭思考”选项，也不得覆盖用户明确声明的兼容性限制。检查基本档位内容和用户显式关闭推理能力的情况。
FR-053无法判断模型能力时，应提示用户补充配置，而不是猜测能力或静默失败。模型目录缺少信息时能看到明确诊断，原配置不被破坏。

4.5 只读反馈与用户选项

编号需求验收方式
FR-060对话输入区应能只读显示当前模式与最近实际执行档，并可查看调度理由。Auto 显示 Auto 而非某一步的固定档；无实际档时不得编造。
FR-061轨迹视图可显示各步骤实际使用的模型与档位；归属不明时宁可不显示，不得错标到其他会话。切换会话、子代理、历史会话及并排视图。
FR-062对话流中的工具小注默认关闭；用户主动开启后才能显示。检查默认状态、开启后刷新及关闭后的恢复。
FR-063所有选项通过配置文件调整，客户端不新增设置控制；显示开关不影响实际调度。修改配置后检查界面与调度是否按各自职责变化。
FR-064只读诊断应帮助用户理解实际档位与理由，不得提供远程修改配置或会话的入口。检查诊断功能没有写操作，且不展示任务正文或凭据。

5. 原生全局选择记忆 F-06 · 冻结插件需求，复用 DSH

2026-11-16 出品人确认：使用 DSH 原生全局选择记忆，不要求每个接入方式与模型分别记忆，冻结原 F-06 插件功能。DSH 保存最近一次明确选择的供应商、模型和逻辑 Auto/具体档；插件不得另建偏好库，也不得把 Auto 单步实际档写回成人工选择。

编号当前需求验收方式
FR-070用户明确选择 Auto 或具体档后，新建会话及应用重启后由 DSH 恢复最近一次全局选择。分别验证 Auto、具体档、新建会话和完整重启；插件无重复记忆开关。
FR-071只保留一份原生全局默认选择，不建立 provider+model 偏好表。切换模型时遵循原生目标模型默认方式，不恢复旧模型的独立档位。两个模型交替选择后，确认新会话只恢复最近全局选择，切换模型不套用旧模型偏好。
FR-072原生恢复 Auto 后必须保持逻辑 Auto 并持续调度，不得变成上一次某一步的实际执行档。Auto 经历多个不同实际档后新建会话，原生选择器仍显示 Auto，各步按证据执行。
FR-073当前会话的明确选择始终优先；用户中途改选后立即生效，并由原生机制成为新的全局选择。恢复旧选择后立即改选，检查当前步骤、后续步骤及下一会话。
FR-074当前明确选择与明确继承优先；没有当次选择时使用原生全局默认。只有原生选择缺失时，才沿用插件既有默认档与宿主默认规则。覆盖当前选择、子代理继承、原生 Auto/具体档、原生选择缺失及插件默认值。
FR-075插件不得为了让旧模型的具体档适配当前模型而寻找相邻档。模型切换与不支持档位的处理遵循原生目标模型能力和安全回退。切换到能力不同的模型，确认没有跨模型 nearest 换算或伪装成人工选择。
FR-076只有原生明确选择流程更新全局记忆；插件的 Auto 计算结果、固定默认值和子代理继承不得写回全局选择。插件不再写入任何具体档位，固定默认档与子代理固定档只影响当步实际发送。连续自动调度、使用默认档和子代理执行后，原生全局选择不被污染；一轮结束后原生选择器的值与回合开始时一致。
FR-077全局选择由 DSH 保存在对应本机配置环境中，插件不保存第二份偏好或任务正文。不同配置环境不得共享插件调度记录。检查两个配置环境；插件数据中不存在偏好副本或简报正文。原生记忆的清理由 DSH 负责，不再承诺删除插件数据会清除它。
FR-078原生选择器呈现逻辑 Auto/具体档；插件只读徽标和轨迹呈现实际执行档，不新增第二套偏好控制。新会话打开原生选择器即可看到恢复结果；Auto 下选择器保持 Auto，徽标与实际档位一致。
与整轮 Auto 的关系：DSH 负责“开始时恢复什么”，插件负责“开始之后是否持续自动”。恢复 Auto 后仍按 FR-040 逐步调度；恢复具体档后仍按人工选择直通。

7. 本地记录、隐私与可删除性

  • 诊断记录：保存最近调度模式、实际档位和必要信号，用于展示与研究；会话正文不属于公开展示内容。
  • 原生选择记录：DSH 保存最近供应商、模型和逻辑选择；插件不另存偏好，不保存用户简报或工具输出。
  • 配置环境隔离：不同用户配置环境的调度记录不得互相覆盖或共享；原生全局选择遵循 DSH 自己的配置环境边界。
  • 记录有界：诊断信息采用有限保留，不因长期使用无限增长；原生只保留一份最近全局选择，插件不维护逐模型历史。
  • 可删除：移除插件及其本地数据后，插件调度记录与界面应一并消失；DSH 原生全局选择由 DSH 管理，不伪装成插件数据。
  • 公开文档：不得包含个人路径、账号、密钥、会话全文或供应商凭据。

F-03 与 F-05：同一个背景，两项不同职责

你的理解抓住了共同背景：模型真实能接收的档位名称、数量或语义，与本项目使用的低—高—最高强度并不总是一致，因此需要能力识别与映射。但两项不能合并为一个需求：F-03 决定“谁有权改写用户配置”，涉及自动补写、主动关闭与持久墓碑；F-05 决定“从哪里知道模型真实能力”，涉及本地知识库或供应商原始列表。即使 F-05 能准确发现能力，也仍要由 F-03 决定能否写配置；反过来，即使 F-03 获得写权限，也仍需要可靠的能力来源。

F-07 背景：官方 Auto 与本项目 Auto 不是同一种机制

有官方证据，但要精确理解。dsh-agent 0.2.2-alpha.2 的 Model selection 文档明确说明：省略 effort 使用适配器默认值；Web/ACP 用户选择直接记录选择，因此省略 effort 意味着 Auto。dsh-agent-loop 同版本文档也说明，步骤准备前固定模型选择，省略的 effort 由适配器默认解析。由此可确认官方 Auto 语义存在，但不能把它理解为本项目这种注入到档位列表中的实体档位，更不是动态调度器。

界面字样也已直接核实：0.2.2 官方模型选择界面在“未选择具体档、使用供应商默认”时，将选项和当前档位标题显示为 Default，中文界面也同样显示 Default；该官方界面代码没有把这项显示为 Auto。因此，本项目的 Auto 不需要因官方命名而变更。

比较维度官方 Auto本项目 Auto
界面字样默认方式显示为 Default。动态调度选择显示为 Auto，保持不变。
本质省略具体 effort，让供应商适配器采用默认方式。一个持续的逻辑选择；内部每一步算出具体档。
决策依据公开文档未表明存在任务分类、错误、信息量或节俭证据调度。任务起点 + 困难与事件 + 信息量 − 节俭，再映射到真实档位。
变化方式记录的选择持续有效，直到用户或程序重新选择。用户保持 Auto 不变，实际执行档可随步骤变化。
二者关系提供模型选择与适配器默认机制。把官方选择机制当作未来迁移接缝，而不是用官方 Auto 替代调度器。
当前有效决策：F-01/F-02 的整轮 Auto 目标已交付（当前选择同步解析，插件不写具体档位）；F-06 冻结插件需求并复用 DSH 原生全局选择记忆；F-04 已否决；F-07 的 Auto 名称保持不变。F-03、F-05 为中等重要、中等紧急的延期裁决项；F-07 的徽标迁移与 F-08～F-12 均为低重要、低紧急的延期项，均未在本轮实施。

11. 当前边界与后续待定事项

  1. 宿主版本：DSH 0.2.2 支持已交付，与 0.2.1 双路径共存；允许清单之外的宿主版本仍拒绝加载，新的宿主版本需要先补契约测试再放开。
